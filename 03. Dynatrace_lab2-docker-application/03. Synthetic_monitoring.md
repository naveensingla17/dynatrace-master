# Synthetic Monitoring

## What it is

Synthetic monitoring is **proactive** monitoring. Dynatrace runs scripted checks against your applications and APIs from chosen locations, at a set frequency, even when no real users are active. It checks two things:

| Check | Question it answers | Example |
|-------|--------------------|---------|
| **Availability** | Is the app or API up? | The request returns `200 OK` |
| **Performance** | How long does it take to load or respond? | The page loads in 2.3 s |

> Real User Monitoring (RUM) shows what real users experienced. Synthetic monitoring tests the app on a schedule, so you can find problems before users do.

## Monitor types

| | HTTP monitor | Browser monitor |
|---|---|---|
| **What it does** | Sends HTTP requests and checks the status code, response time and content | Loads the app in a real browser. A *single-URL* monitor loads one page. A *clickpath* replays a recorded user journey, such as search → book → pay |
| **Output** | Response details (status code, headers, body), often in JSON | Screenshots of the page, plus load timings |
| **Use it for** | APIs and simple endpoint availability | Page load performance and critical user journeys |

## Locations

- **Public locations:** Run by Dynatrace around the world. They test apps that are reachable from the internet.
- **Private locations:** Run on your own Synthetic-enabled ActiveGate. They test internal apps.
